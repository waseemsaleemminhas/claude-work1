# Ironclad Tech — Sales sheet automation

Single Apps Script file (`Code.gs`) that lives inside one Google Sheet and gives staff a
web page for entering and editing records. Pasted into the Sheet by hand; this repo is the
source of record, not a deployment target.

## The Sheet

[IronCladSales_with_Summary](https://docs.google.com/spreadsheets/d/1vWEmUlvH7kk2uwxrMjbsjIkF19d7rPcYoPhc0Dh1CK8/edit)
(id `1vWEmUlvH7kk2uwxrMjbsjIkF19d7rPcYoPhc0Dh1CK8`)

| Tab | Role |
|---|---|
| `Sales` | Closed sales. Columns A–AE, headers have typos that must be kept (`Account Nmumber`, `Beneficary Names`, `Beficiary DOB`). |
| `Dupes Call backs` | Call backs / duplicates. `CARRIER` is column I, added 2026-10-01 after `EXISTING INS`. |
| `Summary` | Hand-built formulas. **Only references `Sales!` columns plus `'Dupes Call backs'!A`** — check it before moving any Sales column. |
| `_Helpers` | Per-row normalised Agent / Carrier / Closer, feeds the Summary leaderboards. |
| `Staff Access` | Email · Name · **Access Code**. The access list. |
| `Access Log` | Time · Email · What · Result. Appends only; SSN appears as last-4 only. |

## How the script works

`doGet` serves one HTML page (built as strings in `Code.gs`, no separate .html files) with
three screens: **New Sale**, **New Call Back**, **Edit a record**. Client calls
`webBoot` / `webSubmit` / `webLookup` / `webSave` over `google.script.run`.

- Both forms are generated from `SALES_FIELDS` / `DUPES_FIELDS`. Add a field there and it
  appears on the page, in the sheet validation, and in the old forms — one place only.
- `RULES` holds every format check. Applied in the browser, again in `prepare_()` on the
  server, and as sheet Data validation via `applySheetValidation()`. Never trust the client.
- `prepare_()` is the single funnel: required checks, state code, dates, fixed lists,
  `RULES`, then `clean_()`. Both the page and the legacy form handlers go through it.
- Fields tagged `shared: 'carrier'` pool their dropdown across both tabs. Fields with
  `after:` are created on the tab in that position if missing (`ensureColumnAfter_`).
- **Edit** is by full SSN only, nothing can be listed. SSN renders locked (it is the key).
  `webSave` compares against `prepare_(before)` — "$52.84" and "52.84" are the same value —
  and writes only changed cells, so `Remarks - Anas/ Waseem` and anything else management
  keeps in the row survives. Changes log as `field: old -> new`; SSN / routing / account
  log as "changed" with no value.
- A stored value that is not on a dropdown is added to that dropdown as a selected option,
  so opening an old row (e.g. `non smoker`, which is not the seed spelling) and saving it
  cannot silently blank the cell.

### Auth — why access codes exist

All staff are on `gmail.com`, not a Workspace domain. With the web app deployed as
"Execute as: Me", `Session.getActiveUser().getEmail()` returns `''` for them, so identity
alone cannot be enforced. `findStaff_()` therefore tries the Google account first and falls
back to a per-person 8-char code (no `0/O/1/I`) stored on `Staff Access`, generated by
`refreshStaffCodes_()` and never regenerated once set. The browser keeps it in
`localStorage`. The alternative — "Execute as: user" — would require giving every staff
member edit access to the spreadsheet, defeating the point.

## Deployment

Staff link (web app, `/exec`):
`https://script.google.com/macros/s/AKfycbwl9tQEBecx-jTUi7S_4iK2rPR2EaP7LRGsSFoSI840DXf9RYpg/exec`

Deployed 2026-10-01 · Execute as: **Me** · Who has access: **see open item below**.

- **After pasting a new `Code.gs`**: Deploy → Manage deployments → ✏️ → Version: **New
  version** → Deploy. The URL never changes. A new *deployment* would mint a new URL — don't.
- Codes: menu **Ironclad Forms → Staff access codes**. They are deliberately **not** in this
  repo; the `Staff Access` tab is the only copy.
- Menu: set up / update everything · show the staff page link · staff access codes ·
  update validation · refresh choice lists (old forms) · fix routing numbers ·
  close the old Google Forms.
- `setup()` is idempotent — safe to re-run after any paste.

### Smoke test after a deploy

Code gate → **Edit a record** → SSN `214-48-1067` (Ruth A Allen, `Dupes Call backs` row 2)
→ change Carrier → Save → `Access Log` should show
`Edit — Dupes Call backs row 2` / `Carrier: "" -> "..."`.

An unauthenticated `curl` of the `/exec` URL cannot verify the access setting: Google
returns the same `404` for a restricted deployment and for a deployment id that does not
exist (verified against a bogus id). Only a signed-in non-owner can tell you.
"Sorry, unable to open the file at present" = Drive refused, the script never ran — either
the visitor is signed out, or access is still *Only myself*.

## Testing

No test runner in the repo. The approach that worked, run from the scratchpad with a
`new Function(...)` wrapper around `Code.gs` and stubbed Apps Script globals:

1. Pure logic — `prepare_`, `clean_`, `stateCode_`, `editValue_`, date parsing, and a
   round-trip proving an untouched row re-validates to byte-identical values.
2. A mock `SpreadsheetApp` (2D arrays with `getRange`/`getDisplayValues`/`setValues`) to run
   `webBoot` → `webSubmit` → `webLookup` → `webSave` against a fake sheet.
3. `jsdom` (`npm i jsdom --no-save`, run with `NODE_PATH=.../node_modules`) loading
   `doGet().html` with `google.script.run` wired to the real server functions — clicks the
   real buttons. Stub `window.scrollTo` and `scrollIntoView`; wait for the `load` event.

96 checks passed. Two real bugs came out of it: comparing display text to stored values
produced phantom edits, and a legacy off-list dropdown value was silently blanked on save.
